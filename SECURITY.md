# BrineSearch Security Policy

## Reporting a vulnerability privately

Please **do not open a public issue** for a suspected vulnerability, exposed credential, private field record, or abuse technique.

Use GitHub's private vulnerability-reporting flow instead:

1. Open the repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Include the affected URL or function, reproduction steps, impact, and any screenshots or logs that do not expose unrelated private data.

If private vulnerability reporting is temporarily unavailable, contact the repository owner privately and ask for a secure reporting channel before sending exploit details.

## What to expect

BrineSearch will acknowledge a credible report as soon as practical, preserve evidence, validate the issue, and prioritize fixes according to driver safety, data exposure, account compromise, and service abuse risk. Please allow time for a production fix before publishing technical details.

## Supported production version

Security fixes are applied to the current production branch, `main`, and the live site at BrineSearch.com. Older exported ZIP files, local copies, and forks are not supported.

## Scope reminders

Never test by changing live pad directions, road facts, mileage, gate information, or another person's Field Feed content. Use the smallest safe proof of concept and stop once unauthorized access is demonstrated.
